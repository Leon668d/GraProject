## 7. 我怎么验收

建议按三层来验收，不要只看训练日志。

### 7.1 第一层：文件与模型验收

目标：确认训练产物和正式模型文件存在。

检查点：

- `training_runs/homography_highres_20260414/history.json` 存在
- `training_runs/homography_highres_20260414/multiscale_homography_best.pth` 存在
- `models/multiscale_homography_best.pth` 存在

通过标准：

- 三个文件都存在
- `models/` 目录内可以看到正式 homography 模型

### 7.2 第二层：接口与系统验收

目标：确认 Web 端能真正选到并调用最新模型。

验收步骤：

1. 启动 Web：

```powershell
cd gra\web_system\web_app
python app.py
```

2. 浏览器打开：

```text
http://localhost:5000
```

3. 登录后进入控制台。

4. 在模型下拉框中选择：

```text
multiscale_homography_best.pth
```

5. 上传一组 SAR / 光学图像。

6. 点击开始配准。

7. 检查是否正常生成：

- 棋盘格图
- 伪彩色融合图
- 差分图
- 轮廓叠加图
- 注册结果下载文件

通过标准：

- 页面不报错
- 结果图正常显示
- 历史任务记录正常生成
- 详情页可打开

### 7.3 第三层：效果验收

目标：确认新模型不是“能跑”，而是“更好”。

建议准备 `10~20` 对固定样例，按以下方式比对：

- 旧模型：`multiscale_highres_ft_best.pth`
- 新模型：`multiscale_homography_best.pth`

每个样例都记录：

- 总耗时
- difference mean
- 结果图主观效果
- 是否优于旧模型

建议重点比较：

- `checkerboard.png`
- `false_color_overlay.png`
- `difference_map.png`
- `contour_overlay.png`

通过标准：

- 至少大部分样例上新模型效果不差于旧模型
- 在典型困难样例上，新模型有明确改进
- 可整理出论文实验图和答辩图

## 8. 建议的正式验收结论标准

如果要说“这一阶段通过验收”，建议至少满足以下条件：

1. `homography` 正式模型文件已进入 `models/`
2. Web 端可手动选择并成功推理
3. 固定样例集上能稳定输出结果图
4. 结果优于或至少不差于当前主用 translation 模型
5. 有训练记录、结果图、对比表三类证据

只有同时满足这几条，才建议在论文和答辩中把它作为“当前正式成果”。
